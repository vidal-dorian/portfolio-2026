API iTop

En bref

Une API REST interne en C# / ASP.NET Core qui fait communiquer les applications internes de l'entreprise avec iTop, un outil ITSM/CMDB open source, pour mettre à jour la CMDB.

Contexte
Stage
Période
Avril – août 2026
Technos
C#, ASP.NET Core, RestSharp, MSTest, Swagger / OpenAPI, iTop / OQL
Code source
Projet interne, non public
SourceApplications internes
API RESTC# / ASP.NET Core
ITSM / CMDBiTop

Détails

L'API sert d'intermédiaire entre les consommateurs internes et iTop : elle dialogue avec son API REST/JSON via des requêtes OQL (Object Query Language).

Le projet suit une architecture en couches stricte (Controllers → Services → DTOs → Models), avec une modélisation métier dédiée aux entités du CMDB : serveurs, bases de données, applications web, instances logicielles.

Points clés

  1. Architecture en couches (Controllers → Services → DTOs → Models)
  2. Construction dynamique de requêtes OQL et gestion de leur échappement
  3. Couverture de tests systématique (DTO, Service, Controller) avec MSTest
  4. Documentation API via Swashbuckle / OpenAPI
  5. Analyse statique et qualité de code (SonarQube / Roslyn)

Synchro iTop

En bref

Une extension du framework open source de collecte de données de Combodo pour iTop, qui synchronise automatiquement des données fournisseurs et clients vers le CMDB, en remplacement d'une saisie manuelle.

Contexte
Stage
Période
Avril – août 2026
Technos
PHP, OAuth2, REST API, iTop / Combodo, ETL
Code source
Projet interne, non public
SourcesAPI externes
CollecteCollector PHP
ExportCSV
ITSM / CMDBiTop

Pipeline de synchronisation

  1. API externeOAuth2
  2. Authentificationclient-credentials
  3. CollectorPrepare / Fetch
  4. Modelmapping vers les attributs iTop
  5. Export CSVfichier intermédiaire
  6. synchro_import.phpdéfinition JSON
  7. synchro_exec.phpréconciliation dans iTop

Détails

Les données viennent d'API REST externes protégées par OAuth2 et passent par le framework itop-data-collector-base avant d'être réconciliées dans iTop.

Le travail a surtout porté sur la fiabilisation d'une première implémentation fragile : diagnostic d'échecs de configuration silencieux, explicitation de la gestion des erreurs HTTP, et correction d'une fuite d'identifiants OAuth2 en clair dans les logs, identifiée lors d'une revue de code.

Points clés

  1. Authentification OAuth2 (client-credentials)
  2. Pipeline ETL vers les webservices de réconciliation iTop
  3. Gestion explicite des erreurs HTTP et logging structuré
  4. Pattern reproductible pour l'ajout de nouvelles sources de données

PHP / SQLite / TMDBPersoSeptembre 2026Dorian Vidal © MMXXVI

Watchd

En bref

Une application web personnelle pour gérer sa collection de films et de séries, branchée sur l'API TMDB.

Contexte
Projet personnel
Période
Septembre 2026
Technos
PHP, SQLite, PDO, API TMDB, HTML / CSS, JavaScript, Cloudflare

Détails

On recherche un titre via l'API TMDB (recherche en direct, tendances) et on l'ajoute à sa collection, puis on le marque « à voir », « en cours » ou « vu », avec un suivi par saison pour les séries.

On peut noter ce qu'on a vu sur 10 et laisser un commentaire. Les films d'une même saga sont regroupés, avec une fiche détaillée (bande-annonce YouTube) et une interface « cinéma » responsive, sur mobile comme sur PC.

Points clés

  1. Recherche en direct et tendances via l'API TMDB
  2. Statuts « à voir », « en cours », « vu » et suivi par saison
  3. Notes sur 10 et commentaires
  4. Regroupement des sagas et fiches détaillées
  5. CSS écrit à la main, responsive

FastAPI / ReactPersoAoût – octobre 2026Dorian Vidal © MMXXVI

GestionProjet-IUT

En bref

Un outil web de suivi de projet agile (Scrum) pour des équipes étudiantes : heures de travail, sprints synchronisés depuis GitHub, burndown chart et diagramme de Gantt.

Contexte
Projet personnel
Période
Août – octobre 2026
Technos
Python, FastAPI, SQLAlchemy, MySQL, React 19, TypeScript, Vite, Docker, GitHub Actions

Détails

Les membres saisissent leurs heures de travail par catégorie, synchronisent les issues et les sprints depuis GitHub, et suivent l'avancement avec un dashboard, un burndown chart et un diagramme de Gantt.

L'outil génère aussi les comptes-rendus des cérémonies Scrum (daily, planification, review, rétrospective) en Word, et des exports Excel des heures.

Points clés

  1. Saisie des heures par catégorie, dashboard et exports Excel
  2. Synchronisation des issues et des sprints depuis GitHub
  3. Burndown chart et diagramme de Gantt
  4. Comptes-rendus de cérémonies Scrum générés en Word
  5. Authentification par Cloudflare Access (JWT)
  6. Docker Compose, CI/CD GitHub Actions, tests pytest
  7. Déployé sur un Raspberry Pi via Cloudflare Tunnel
